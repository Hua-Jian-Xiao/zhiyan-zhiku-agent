# 数据结构与算法

## 第 1 章 复杂度与线性结构

### 1.1 时间复杂度与空间复杂度

复杂度分析用输入规模的增长趋势评估算法成本。大 O 记号忽略常数与低阶项，描述算法在最坏情况下的渐近上界。常见复杂度包括 O(1)、O(log n)、O(n)、O(n log n) 和 O(n²)。

空间复杂度统计算法额外使用的内存。递归调用栈、哈希表和辅助数组都可能成为空间瓶颈。实际工程中还要考虑缓存局部性、常数因子和输入分布。

分析复杂度时要明确基本操作和输入规模。不能仅凭代码行数判断效率；嵌套循环、隐式拷贝和排序调用都需要计入成本。

### 1.2 数组、链表、栈与队列

数组支持 O(1) 随机访问，但中间插入可能触发搬移；动态数组扩容需要均摊分析。链表插入删除灵活，却失去连续内存的缓存优势。

栈遵循后进先出，适合表达式求值、括号匹配和深度优先搜索；队列遵循先进先出，适合广度优先搜索和任务调度。双端队列可在两端高效插入删除。

选择数据结构时应从访问模式出发，而不是机械记忆操作复杂度。频繁随机访问优先数组，频繁中间插入可考虑链表，滑动窗口与单调队列可显著降低复杂度。

### 1.3 哈希表与集合

哈希表通过哈希函数把键映射到桶，实现平均 O(1) 的查找、插入与删除。冲突处理包括链地址法和开放寻址；负载因子过高会显著增加冲突。

哈希表的最坏复杂度可能退化到 O(n)，因此需要关注哈希质量与扩容策略。Python dict、Java HashMap 等实现细节不同，迭代顺序和内存占用也不同。

哈希适用于去重、计数、缓存和建立索引。对于需要范围查询或有序遍历的场景，平衡树往往更合适。设计检索系统的倒排索引时，也会使用类似哈希与映射的结构。

## 第 2 章 树、图与算法设计

### 2.1 二叉树与堆

二叉树每个节点最多有两个子节点。二叉搜索树在平衡时支持 O(log n) 查找，但可能退化为链。AVL 树与红黑树通过旋转维持平衡，是许多标准库有序映射的基础。

堆是一棵完全二叉树，满足父节点优先级高于或低于子节点。二叉堆支持 O(1) 查看堆顶和 O(log n) 插入删除，可用于优先队列、Top-K 和 Dijkstra 算法。

树遍历分为前序、中序、后序和层序。递归写法直观，迭代写法能避免深递归爆栈。遍历顺序不同，构造与序列化的结果也不同。

### 2.2 图的遍历与最短路径

图由顶点和边构成，可用邻接表或邻接矩阵表示。邻接表适合稀疏图，邻接矩阵适合快速判断两点是否相连。DFS 适合连通性、环检测和拓扑排序，BFS 可求无权图最短路径。

Dijkstra 适用于非负权图，基于优先队列实现；Bellman-Ford 可处理负权边并检测负环；Floyd-Warshall 求所有点对最短路径。拓扑排序要求图是有向无环图。

知识图谱本质上也是图。知识点依赖可以用有向边表示，前置知识形成从基础到进阶的 DAG。图算法可用于依赖检查、学习路径规划和知识链路展示。

### 2.3 动态规划

动态规划把大问题拆成重叠子问题，通过保存状态避免重复计算。设计步骤包括定义状态、写出转移方程、确定初始条件和遍历顺序。状态设计决定了算法的正确性与复杂度。

背包、最长公共子序列和最短编辑距离是经典问题。滚动数组可以降低空间复杂度，但必须保证状态转移依赖的顺序。许多序列与区间问题也可以通过记忆化搜索实现。

动态规划并不适用于所有问题。需要满足最优子结构，并确保子问题之间没有后效性。分析时应计算状态数量与转移成本，确认复杂度可接受。
