# 计算机网络

## 第 1 章 分层模型与传输层

### 1.1 网络分层与 TCP/IP

网络协议采用分层设计以降低复杂度。OSI 模型包含物理层、数据链路层、网络层、传输层、会话层、表示层和应用层；TCP/IP 模型把功能归纳为网络接口层、网际层、传输层和应用层。

分层提供了清晰的接口边界，使不同厂商和设备可以互操作。IP 负责主机之间的寻址与路由，TCP/UDP 负责进程之间的通信，HTTP、DNS 等应用协议建立在传输层之上。

理解网络问题时需要明确所在层次。例如浏览器无法访问网站可能是 DNS、TCP 握手、TLS 或 HTTP 状态问题；按层次逐项排查比盲目重试更有效。

### 1.2 TCP 可靠传输

TCP 通过序列号、确认应答、超时重传和校验和提供可靠字节流。接收方使用累计确认告诉发送方已经收到哪些数据；乱序包会在缓冲区中等待完整后再交付应用。

滑动窗口允许发送方在未收到确认时连续发送多个段，提高吞吐量。流量控制通过接收窗口防止接收方被淹没；拥塞控制则根据网络状况调整发送速率。

TCP 三次握手建立连接，四次挥手关闭连接。TIME_WAIT 用于保证旧连接报文消失并让对端收到最终确认。高并发短连接场景应使用连接池或改用合适的持久连接策略。

### 1.3 TCP 拥塞控制

拥塞控制根据网络反馈调整发送窗口，避免过多数据导致网络崩溃。慢启动阶段窗口指数增长，达到阈值后进入拥塞避免，线性增长；丢包时根据算法减小窗口。

经典算法包括 Reno、CUBIC 和 BBR。CUBIC 根据时间函数增长窗口，适合高带宽长距离网络；BBR 通过测量带宽和往返时延主动估计网络瓶颈，不完全依赖丢包信号。

拥塞控制与队列管理、应用发送策略共同决定实际吞吐。线上排查要区分带宽限制、随机丢包与缓冲区膨胀，观察 RTT、重传率和吞吐变化，而不是只看是否“丢包”。

## 第 5 章 应用协议与安全

### 5.1 HTTP 与 HTTPS

HTTP 是请求—响应式应用层协议。请求包含方法、路径、头部和可选正文；响应包含状态码、头部和正文。缓存控制、内容协商与连接复用是性能优化的重要部分。

HTTP/2 通过多路复用、头部压缩和服务器推送减少延迟；HTTP/3 基于 QUIC，使用 UDP 实现连接建立与拥塞控制。不同版本的实际收益取决于网络环境与客户端支持。

HTTPS 通过 TLS 提供加密、身份认证与完整性。证书校验、密钥交换与 SNI 是实现细节；部署时要关注证书有效期、TLS 版本和加密套件，避免中间人攻击。

### 5.2 DNS 与 CDN

DNS 把域名解析为 IP 地址，形成分层分布式系统。递归解析器从根域、顶级域到权威服务器逐级查询，并缓存结果。TTL 决定缓存时间，影响故障切换速度。

DNS 轮询可以实现简单负载分发，但健康检查和会话保持能力有限。CDN 通过边缘节点缓存静态资源，使用就近访问降低延迟，并通过缓存键与回源策略控制一致性。

DNS 故障常表现为“网站打不开但 IP 可访问”。排查时要检查解析结果、TTL、CNAME 链与本地缓存，避免在错误层次修改应用代码。

### 5.3 网络安全基础

网络安全需要同时考虑机密性、完整性和可用性。常见风险包括注入、越权、跨站脚本、跨站请求伪造、重放攻击和敏感信息泄漏。

防护措施包括最小权限、输入校验、参数化查询、输出编码、HTTPS、短期令牌与速率限制。认证解决“你是谁”，授权解决“你能做什么”，两者不能混为一谈。

日志与审计是安全运营的重要基础。日志不应记录密码、完整令牌或密钥；需要设置保留期限与访问控制。发现泄露后应立即轮换凭据，并评估影响范围。
