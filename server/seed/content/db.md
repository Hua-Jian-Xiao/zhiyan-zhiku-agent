# 数据库系统

## 第 1 章 关系模型与查询

### 1.1 关系模型与范式

关系数据库用二维表表示实体与联系。关系模式定义属性与约束，主键唯一标识一行，外键保证跨表引用完整性。SQL 通过 SELECT、INSERT、UPDATE、DELETE 操作数据。

范式化通过拆分表减少冗余与更新异常。第一范式要求属性原子，第二范式消除非主属性对候选键的部分依赖，第三范式消除传递依赖。过度范式化会增加连接开销，实际设计需要在一致性与查询性能之间权衡。

数据完整性包括实体完整性、参照完整性和用户自定义约束。合理使用唯一索引、非空约束与检查约束，可以把一部分业务规则交给数据库执行。

### 1.2 SQL 查询与聚合

SQL 查询通常由 FROM、WHERE、GROUP BY、HAVING、SELECT、ORDER BY 和 LIMIT 组成。聚合函数对分组数据计算统计值，窗口函数可以在不折叠行的前提下完成排名、累计与移动平均。

连接用于组合多张表，内连接只保留匹配行，左连接保留左表全部行。子查询可以出现在 WHERE、FROM 或 SELECT 中；相关子查询会引用外层查询的字段。

编写查询时要明确执行顺序和 NULL 语义。COUNT(*) 与 COUNT(column) 结果可能不同，NOT IN 遇到 NULL 可能产生意外结果。复杂查询应通过执行计划和测试数据验证。

### 1.3 索引与 B+ 树

索引通过额外的数据结构加速查询。B+ 树将有序键组织为多路平衡树，叶子节点通过链表连接，适合范围查询和排序。联合索引遵循最左前缀原则。

索引会占用空间并增加写入成本。低选择性的列通常不适合单独建索引；频繁用于过滤、连接和排序的列更值得索引。覆盖索引可以让查询直接从索引返回结果，减少回表。

查询优化器根据统计信息选择索引和连接顺序。统计信息过期可能导致错误计划，应定期更新。使用 EXPLAIN 分析扫描行数、连接方式与临时表开销，是排查慢查询的起点。

## 第 6 章 事务与向量检索

### 6.1 事务与 ACID

事务是一组要么全部成功、要么全部失败的数据库操作。原子性保证部分失败会回滚，一致性保证约束不被破坏，隔离性控制并发事务之间的可见性，持久性保证提交后的数据不会丢失。

数据库通过 undo 日志、redo 日志和锁机制实现事务。长事务会持有资源并阻碍清理，应尽量缩短事务范围。应用层重试要幂等，避免重复提交。

事务并不替代业务一致性设计。跨服务操作需要考虑分布式事务、补偿或最终一致性；不能因为数据库支持事务就忽略幂等与状态机约束。

### 6.2 隔离级别与并发控制

SQL 标准定义读未提交、读已提交、可重复读和串行化四种隔离级别。不同级别对应脏读、不可重复读和幻读的可见性权衡。MySQL InnoDB 默认使用可重复读，并通过 MVCC 提供一致性快照。

MVCC 让读写互不阻塞，但需要清理旧版本。间隙锁与临键锁用于处理范围条件，可能增加死锁概率。应用应尽量按固定顺序访问资源，并设置合理的锁等待超时。

死锁并不可怕，数据库通常能检测并回滚其中一个事务。重要的是捕获死锁错误并进行有限重试，同时通过日志定位冲突热点。

### 6.3 向量数据库与相似检索

向量数据库面向高维向量的近似最近邻检索。常见索引包括 HNSW、IVF 与 PQ。HNSW 通过分层图结构平衡召回率与查询速度，适合低延迟在线检索；IVF 通过聚类缩小搜索范围。

MySQL 8 没有原生向量类型，可以把 embedding 存为 JSON 并在线做精确余弦相似度计算。数据量较小时这种方式简单可靠；数据增大后应迁移到专用向量数据库或支持 pgvector 的 PostgreSQL。

检索系统需要同时考虑召回率、延迟、更新成本和可解释性。稠密向量擅长语义相似，BM25 擅长精确术语；混合检索再经过重排序，通常比单一方法更稳定。
